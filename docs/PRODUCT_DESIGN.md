# ClickCap 제품·기술 설계서

## 1. 목표와 범위
ClickCap은 Chrome 확장 프로그램에서 사용자가 현재 탭 전체 또는 직접 지정한 사각형을 캡처하고, 녹화를 일시정지/재개/중지한 뒤 재생 가능한 파일로 내려받도록 한다. 산출물은 재생 가능한 WebM 영상이며, 해상도·FPS·비트레이트 등 크기와 품질을 제어한다. 다른 형식이 필요하면 사용자가 내려받은 WebM 파일을 별도 도구로 변환한다. 오디오, 클릭 줌, PonsLink 연동은 기존 기능으로 보존한다.

중요한 제품 원칙: ClickCap은 브라우저에서 녹화 가능한 WebM만 다운로드한다. 별도 포맷 변환 기능이나 변환기 의존성은 포함하지 않는다. 과거 미사용 `src/worker/format-converter.js`는 잘못된 MP4/GIF 결과를 만들 수 있어 제거했다. 사용자는 필요하면 별도 도구로 다운로드한 파일을 변환한다.

## 2. 사용자 여정
1. 팝업에서 녹화 모드와 출력 해상도, FPS 및 품질을 설정하고 녹화를 시작한다. 출력 파일 형식은 WebM으로 고정이다.
2. 영역 모드에서는 페이지에서 사각형을 드래그한 뒤 Side Panel에서 녹화를 시작한다. 전체 탭 모드는 바로 시작한다.
3. Side Panel에서 일시정지·재개·중지를 수행한다. 녹화 컨트롤과 crop 표시선은 캡처되는 페이지에 띄우지 않는다.
4. 정지 후 패널은 WebM 다운로드가 완료될 때까지 진행 상태를 표시한다.
5. 브라우저 다운로드가 끝나면 파일을 일반 플레이어에서 재생한다.

## 3. 현재 상태와 핵심 격차
- MV3 확장 구성: 팝업 → service worker → offscreen document 캡처/인코딩. 현재의 주요 데이터 경로와 PonsLink 기능은 유지한다.
- 영역 선택과 WebM 녹화가 제공된다. GIF/MP4/MKV 등 변환은 ClickCap에서 제공하지 않는다.
- 이번 변경에서 Original/1080p/720p/480p 최대 높이 설정과 비율 보존 캔버스 축소를 추가하고 계산을 테스트했다.
- 종료 후 자동 다운로드만 제공하며 미리보기/재생 및 재인코딩 내보내기 UX는 미구현이다.
- 제한된 캡처 호스트, 긴 녹화의 메모리·용량, 다중 모니터/DPR/브라우저 줌, 탭 탐색/종료 오류의 QA가 더 필요하다.

## 4. 아키텍처
- **Popup (`src/popup`)**: 설정 및 세션 제어. 사용자 설정은 `storageManager`로 영속화하고 메시지 스키마는 `MESSAGE_TYPES`를 사용한다.
- **Service worker (`src/background/service-worker.js`)**: 탭 권한/캡처 스트림 획득, 세션 상태, 콘텐츠 스크립트와 offscreen 간 메시지 라우팅. 장시간 미디어 데이터를 보관하지 않는다.
- **Side Panel (`src/sidepanel`)**: 전체/영역 녹화 시작, pause/resume/stop 및 녹화/다운로드 완료 상태를 표시한다. 탭 밖의 브라우저 UI이므로 영상에 포함되지 않는다.
- **Content script (`src/content`)**: 영역 선택기 및 단축키용 레거시 도크를 담당한다. Side Panel 녹화에서는 도크/영역 테두리를 숨긴다. 캡처 원본을 읽거나 다운로드하지 않는다.
- **Offscreen (`src/offscreen`)**: `MediaStream` 수신, crop 및 출력 캔버스 변환, WebM MediaRecorder 인코딩, 종료/정리. 출력 크기 조절은 캔버스 종횡비를 유지하고 원본보다 확대하지 않는다.
- **공유 설정/유틸 (`src/utils`)**: 기본 설정 및 메시지/파일명 정책의 단일 기준점.

데이터 흐름: 팝업은 설정을 저장하고 Side Panel을 열어 녹화를 시작 → service worker가 캡처 스트림을 준비 → offscreen이 crop/scale 후 WebM으로 인코딩 → Chrome downloads API가 완료될 때까지 object URL을 유지하고 이후 정리 → 완료/오류 상태를 UI에 알림. 고용량 Blob을 `chrome.storage` 메시지로 전달하지 않는다.

## 5. 설정 및 출력 계약
- 녹화 영역 좌표는 CSS 픽셀과 캡처 비디오 픽셀을 명시적으로 변환하며 좌표계/viewport/DPR를 기록한다.
- `outputResolution`: `source | 1080 | 720 | 480`; 설정은 출력 높이의 상한, 원본 비율 유지, 확대 금지. 출력 width/height는 정수이며 최소 1px.
- WebM: `MediaRecorder.isTypeSupported`를 기준으로 vp9→vp8→기본 WebM 선택. MIME과 파일 확장자 일치. 이 파일을 유일한 ClickCap 내보내기 형식으로 사용한다.
- 파일명은 확장자와 MIME에 일치한다. Chrome downloads API 완료/중단 상태를 확인하고 다운로드 완료 후 object URL을 정리한다.
- 추가 포맷 변환은 범위에 포함하지 않는다. WebM 파일의 변환은 별도 도구에 맡긴다.

## 6. 오류·보안·성능
- 권한 거부, 보호된 URL, 탭 종료/탐색, 비지원 MIME, 인코더 오류, 다운로드 차단을 별도 사용자 메시지로 표현한다.
- 확장 호스트 권한은 현재 권한을 먼저 검토하고 필요 이상의 권한을 늘리지 않는다. 캡처는 사용자 명시 동작으로 시작하고 상태를 항상 표시한다.
- 녹화 전 예상 픽셀/초 및 메모리 위험을 안내하고, 최대 시간·프레임·메모리 기준은 상수화 및 테스트한다.
- 스트림 트랙, MediaRecorder, 타이머, 비디오 요소, Canvas, object URL은 성공/실패/취소 모든 경로에서 해제한다.
- 오디오 포함 시 트랙이 실제 존재할 때만 연결한다.

## 7. 검증 기준
- 전체/선택 영역 결과가 선택한 좌표만 포함하며 원본 비율과 지정 해상도 상한을 지킨다.
- WebM 결과를 실제 디코더로 열어 재생 가능성, 크기 및 오디오 포함 여부를 확인한다. 다운로드 완료 전에 object URL을 해제하지 않는다.
- 권한 거부·보호 페이지·빈 프레임·녹화 취소·인코딩 오류·다운로드 오류에서 UI와 리소스가 정리된다.
- 설정은 재시작 후 유지되고, 기존 단축키·클릭 줌·PonsLink 동작은 회귀하지 않는다.
- Chrome 최소 지원 버전 116 및 최신 Chrome, 주요 DPR/브라우저 줌을 포함한 수동 E2E 체크리스트를 통과한다.

## 8. 제품 결정과 비목표
- 이번 구현은 Chrome MV3/현재 vanilla JS 구조를 유지한다. 전체 앱 프레임워크 이주, 서버 업로드, 계정/클라우드 저장은 포함하지 않는다.
- 추가 포맷 변환은 하지 않는다. 사용자는 외부 변환 도구를 이용한다.
- 사용자가 지정한 영역은 직사각형 캡처다. 임의 다각형 마스킹/편집 타임라인은 별도 제품 범위다.
